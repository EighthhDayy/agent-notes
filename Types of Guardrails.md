
# Types of Guardrails

Based on where protection is applied, guardrails can be divided into three layers: **Context Layer, Execution Layer, and Data Layer**. These three layers are not arranged according to the order in which requests are processed, but according to **the difficulty of bypassing them**—the lower the layer, the less it depends on the model's own judgment, and therefore the harder it is for a single successful attack to penetrate.

**Context-layer guardrails control what the model can see, intercepting content before it enters the context**, and typically include four mechanisms. **Relevance classifiers** flag off-topic queries, such as a programming assistant receiving an unrelated question like "How tall is the Empire State Building?" **Safety classifiers** detect jailbreaks (Jailbreak, inducing a model to bypass safety restrictions) and prompt injections (Prompt Injection, embedding malicious instructions in input). The key difference between the two is that a jailbreak involves users themselves attempting to bypass the model's safety restrictions, while prompt injection involves attackers indirectly manipulating model behavior through external data (such as web content or documents). **Content moderation** flags harmful or inappropriate input, such as violent or discriminatory content. **Rule-based protection** uses deterministic measures, including blacklists, input length limits, and regular expression filters, to defend against known threats such as SQL injection. Source attribution and the separation of "instructions/data" also belong to this layer.

A representative industrial implementation of context-layer guardrails is Anthropic's Constitutional Classifiers. Its core mechanism consists of three parts. First, **rule-driven**—rules written in natural language (explicitly specifying which content is allowed and which is prohibited) are used to generate synthetic training data for training input and output classifiers. Second, **joint context evaluation**—the newer generation of systems examines user questions and model responses together, because some responses appear completely harmless in isolation (such as "How to use food seasonings"), and only by comparing them with the original question can the system discover that "food seasonings" is actually a code word for chemical reagents. Third, **two-stage screening**—a very lightweight probe (which directly reads the model's internal activations at almost zero cost) first examines all conversations, and suspicious cases are then passed to a stronger classifier for further review rather than being rejected immediately. In this way, even if the first stage produces relatively many false positives, it does not affect the user experience, while costs are also significantly reduced.

However, this layer has a structural limitation: **an Agent operating within the same context has difficulty determining whether it has already been subjected to prompt injection**. Therefore, context-layer guardrails can only reduce the success rate of attacks, but cannot provide guarantees—this is precisely why the two lower layers are necessary.

**Execution-layer guardrails control what the model can do**, validating actions before they actually take effect. Their core mechanism is **tool risk classification**: based on whether an operation is reversible, its permission level, and its financial impact, **each tool is assigned a risk level (low/medium/high), and high-risk operations require additional review or human confirmation**. The key is that such reviews must be performed by mechanisms outside the context—independent review processes, least-privilege credentials, sandbox isolation, and human-in-the-loop mechanisms—otherwise they may be compromised together with the injected Agent. Responses returned to users are also actions (Chapter 4 classifies them as user communication tools), so **output checks** also belong to this layer: **PII filters** examine personal identity information in outputs (such as ID numbers and phone numbers) to prevent unnecessary exposure; **output validation** uses content checks to ensure that responses align with brand values.

**Data-layer guardrails control how the world can ultimately be changed**, delegating "who can perform what operations on which data" to a stable, human-reviewed mechanism for enforcement: database row-level security policies, constraints and validators, controlled views and stored procedures, and access contexts bound by trusted runtimes that cannot be forged. The value of this layer lies in its independence from whether the two upper layers are correct—even if prompt injection succeeds and the generated code completely omits permission checks, unauthorized operations will still be rejected at the data layer.
